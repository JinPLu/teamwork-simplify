# Teamwork Collaborate

Discussion and planning run as one thread. Goals, constraints, and rejections
settled in the discussion carry straight into the plan — nothing settled gets
re-asked at a handoff. Re-judge the trigger when the request changes shape
mid-session; it is not settled once at the opening.

## Method

1. **Rebuild the decision surface before proposing anything.** Establish the
   final goal, what has already been tried on this question, which constraints
   and rejections are settled, and which unknowns would change the goal or the
   acceptance criteria. Build from those facts; do not invent an option from a
   blank page.

2. **Ask one stage of questions at a time.** A stage is the set of decisions
   that belong to the user and do not depend on each other. Ask all of them
   together; hold back every question whose answer depends on this stage. A
   host's question-count limit caps one call, not the batch — split across
   calls rather than dropping questions.

3. **Resolve what you can discover; ask only for a preference or an
   authorization.** Open the file, run the search, read the config yourself.
   Bring back options that are meaningfully different from each other, each
   with its main benefit, its cost, its assumption, and what it commits to.

4. **Recommend when the evidence distinguishes one option, then record what the
   user decides, in their words.** A decision made and a rejection recorded are
   settled: do not reopen either because a search result or a returned line
   looks interesting. When the direction rests on one load-bearing assumption,
   an optional Challenger may attack that frozen assumption read-only before
   the decision is recorded; its absence does not hold up the decision.

5. **Turn the settled direction into a plan in the same thread.** Verify the
   project facts the plan rests on — the real owners, interfaces, dependencies,
   and the nearest verification that already exists. Order the steps by
   dependency, size each one to an outcome, and name what it produces and how
   that is observed. A benchmark, appendix, probe, or extra document is not a
   prerequisite just because it would help explain something.

6. **State the split verdict in the plan, always.** Say whether the ordered
   steps break into independent lines; when they do, dispatch those lines
   through this host's own parallel surface, named in the host's own terms.
   When they do not, name the dependency or the shared path that prevents it.

7. **Integrate each returned line yourself and verify it on the real path**
   before reporting it. A line's own claim that it succeeded is not the
   verification.

8. **Close with the decision, what is still open, and the next authorized
   action.** Once the direction is decided and the user authorizes execution,
   stop discussing and do it.

## Documents

`references/discussion.md`, `plan.md`, `record.md`, `experiment.md`, and
`guide.md` are longer skeletons for the five kinds — use the matching one when
you write. An optional Writer may carry out the write when that does not delay
it; it never decides which document this is or what counts as material.
